# Independent Thunderbolt transport recovery

Research date: November 5, 2026. This records recovered host-controller structures and independently written offline components. It does not describe an activated replacement driver. The application still uses the original management driver; [the work record](../docs/WORK_RECORD.md) owns acceptance and hardware limits.

## Evidence

REA 6.8.0 with Ghidra 12.1.4 inspected the x86_64 slice of DroboTBT 1.4, SHA-256 `cf21793cafa3d7cded2a07b743cb610415b2b44b88f8a79f15ae8493de8b1662`. Selected directory offsets and queue framing were then corroborated against its arm64e slice, SHA-256 `a0c5bb4e5b7bb853ed92973182fbc390ccc3f45713aedf5c8af6b41fbd8a569e`, using the installed Xcode LLVM disassembler. This does not establish complete ARM semantic equivalence or runtime compatibility. Addresses below refer to x86_64 unless marked ARM; none are disk locations or BAR offsets unless explicitly identified as such.

Local ignored receipts under `artifacts/reports/independence/thunderbolt` contain the source identity, exact queries, evidence IDs, pseudocode, and selected complete assembly. The DMA/interrupt follow-up is indexed under `artifacts/reports/controller/thunderbolt` and `controller/deep`. Each `receipts.json` records exact tool queries and evidence IDs. Both original slice hashes were checked again for this follow-up and were unchanged. Decompiled output remains local; the public code was written independently from the recovered field behavior.

The storage/drain follow-up uses REA/Ghidra, LLVM assembly and retained DWARF from the 5D Thunderbolt bridge image `5D.elf`, SHA-256 `5a2dd1200f53adaf646325098294e4c1dc5455d6246ad9d434259c66797c0330`. The separately inventoried 5D3 bridge image hashes to `577f948f659a307ddfe881dc1e385febc6c8c6ec0782570d21bb383b665d1924`; its paths are not certified by the 5D findings below. These bridge images are distinct from the `5D-runesa.elf` BeyondRAID processor image used in the capacity/RMR notes. Bridge addresses below are ARM32 code addresses. Queries, evidence IDs, complete selected assembly and DWARF excerpts remain ignored under `artifacts/reports/drain/`; original host sleep queries are under `drain/original`.

## BARs and port directory

`InitializeController` at `0x0d8c` maps device memory indices 0 and 1. It uses BAR0 for interrupt/register access and BAR1 for the `DroboPort` directory. The previously recovered host-ready doorbell is BAR0 offset `0x21878`, bit `0x200000`. A disconnected read can produce `0xffffffff`. These observations do not establish DMA ownership, mapping lifetimes, or a safe activation sequence.

`IsDroboPortReady` at `0x5d68` checks a non-null address and compares against the C string `DroboPort` with a maximum length of 16. The terminating NUL is significant; bytes after that NUL are not required to be zero. The initialized firmware port has these little-endian, 32-bit relative offsets:

| Directory offset | Target relative to the BAR1 port base | Corroboration |
| --- | --- | --- |
| `0x18` | LUN table | Base-channel initializer `0x42ce` |
| `0x1c` | 64-byte capabilities block | Base-channel initializer `0x42ce` |
| `0x20`, `0x24` | Storage request and response lists | SCSI initializer `0x4d96` |
| `0x28`, `0x2c` | System-control request and response lists | System initializer `0xba98` |
| `0x30`, `0x34` | Transport-manager request and response lists | TM initializer `0xb0a6` |
| `0x38`, `0x3c` | PCI and endpoint interrupt-definition blocks | SCSI initializer `0x4d96` |
| `0x40` | Inquiry identity data | In-driver initializer `0x9f96` |

The capabilities block starts with ten recovered 32-bit values: interface version, transfer mode, maximum transfer bytes, maximum outstanding transactions, maximum LUNs, flags, maximum burst, stall size, maximum SGL entries, and host interface version. `DumpCapabilities` at `0x473a` supplies the labels. Base initialization writes host interface version 1 at capability offset `0x24`; the offline parser never performs that write. The remaining six words are not interpreted.

Selected ARM corroboration: base initialization at `0xd024` loads the same capability/LUN offsets at `0xd088`/`0xd0a0`; SCSI initialization at `0x10080` loads response/request offsets `0x24`/`0x20` at `0x1012c`/`0x10140`; TM initialization at `0x1a888` loads response/request offsets `0x34`/`0x30` at `0x1a928`/`0x1a93c`. ARM request publication at `0x13c54..0x13c80` uses the same 16-byte descriptors. ARM completion selection at `0x141e4..0x14200` selects 32- versus 8-byte entries and reads queue index/transaction ID. Exact excerpts and the bounded claim list are retained in `arm64e-*.asm` and `arm64e-corroboration.json` beside the REA receipts.

Each LUN record is 16 bytes: a nonzero enabled word, a 32-bit block size, and a 64-bit logical block count. The original initial scan examines 32 slots. All of these are host-visible logical geometry, not protected BeyondRAID capacity. The new decoder uses checked multiplication and explicitly calls the product a virtual byte ceiling.

The bounded parser verifies supported interface versions 1–4, offset alignment and bounds, complete capabilities and fixed LUN-table coverage, and nonzero/nonoverflowing geometry for enabled records. Other directory targets are reported as offsets; their entire contents and consistency are not certified by parsing the directory. A decoded snapshot is not a ready device.

## Requests and completions

`ProcessRequests` at `0x7a06` uses an eight-byte list header, then 16-byte descriptors. Header word 0 is the firmware-provided request window; word 1 is the submitted count. Descriptor words are DMA address low, DMA address high, request length, and transaction ID. The original path also writes a queue index and transaction ID into the associated DMA request buffer before ringing the ready interrupt.

`ProcessCompleteRequests` at `0x7fae` rejects the removed-device count sentinel and counts exceeding the matching request window. It selects completion layout by interface version:

| Entry field | Versions 1–3 | Version 4 |
| --- | --- | --- |
| Entry size | 8 bytes | 32 bytes |
| Queue index | `+0x00`, u32le | `+0x00`, u32le |
| Transaction ID | `+0x04`, u32le | `+0x04`, u32le |
| Realized byte count | Read from a separate request extension | `+0x08`, u64le |
| SRB response word | Read from a separate request extension | `+0x14`, u32le |
| SCSI status word | Read from a separate request extension | `+0x18`, u32le |

Version-4 words at `+0x10` and `+0x1c` remain uninterpreted. The original driver treats SRB values 1 and `0x12` as successful service responses, then passes the separate SCSI status onward. Matching an entry or SRB value alone does not establish successful data I/O. The independent codec checks count/allocation limits, queue and transaction association, duplicate entries, and oversized transfers, while retaining version-specific status for the higher-level command policy. Legacy entries cannot supply a realized count or final status by themselves.

These codecs serialize copied bytes only. They neither allocate/dereference DMA addresses nor submit frames. Their offline resource limits are parser policy, not a claim about a device's queue capacity.

## Management is a separate channel

`GetRequestType` at `0x302c`, together with `ProcessParallelTask` at `0x2dc6`, separates storage reads, system-control operations, in-driver emulation, and transport-manager commands. MODE SENSE(10), including the protected-capacity and LUN-information pages, goes to the transport-manager channel. `READ CAPACITY` is handled separately by the in-driver path at `0xa60c`, using the logical LUN table.

This explains why replacing READ CAPACITY with a smaller protected total would address the wrong layer for an existing filesystem. A replacement storage driver must preserve its logical address space. A filesystem view can later report verified protected allocation through its statistics callback, without changing that geometry.

The TM request builder at `0xb338` uses a `0x58`-byte fixed request/response extension before optional 16-byte SGL entries. Recovered fields include transfer flags at `0x20`, data length at `0x24`, buffer/SGL pointer at `0x28`, and the CDB at `0x30`. Data-in starts with flags `0x410020`. The single-segment branch at `0xb727..0xb75f` adds 16 to the fixed length, producing a 104-byte request, copies the first SGL address from `+0x58` to `+0x28`, zeros the SGL length at `+0x60`, and adds flag `0x08`. The direct branch therefore does not require a nonzero length in the trailing SGL record: the transfer length is at `+0x24`.

The common prefix carries its own 32-bit DMA address in a 64-bit field at `+0x00`, queue index/transaction at `+0x08/+0x0c`, an opaque host cookie at `+0x10`, request size at `+0x18`, and channel type 3 at `+0x1c`. OpenDrobo uses a task identifier as the cookie, never a CPU pointer. Response helpers read realized count at `0x40`, SRB response at `0x4c`, and SCSI status at `0x50`; the initial engine consumes version-4 completion entries instead. The new encoder covers only the recovered single-segment data-in branch. Multi-segment TM requests, legacy completions, storage submission, and complete response semantics remain outside this engine.

## Interrupt definitions and removal

`MMIOReadInterruptDefEntry` at `0x8fa7` copies 21 little-endian words, or 84 bytes. `GetInterruptState` at `0x60fa`, the action helpers at `0x61f6..0x62ec`, and `ApplyOperator` at `0x633e` recover these groups:

| Group | Register offset | Declared size | Operand | Operator |
| --- | --- | --- | --- | --- |
| Trigger | `+0x04` | `+0x08` | `+0x0c` | `+0x10` |
| State | `+0x14` | `+0x18` | `+0x1c` | `+0x20` |
| Enable | `+0x24` | `+0x28` | `+0x2c` | `+0x30` |
| Disable | `+0x34` | `+0x38` | `+0x3c` | `+0x40` |
| Clear | `+0x44` | `+0x48` | `+0x4c` | `+0x50` |

Word zero and declared-size semantics remain uninterpreted; the observed accesses are 32-bit. Operator values are 0 AND, 1 OR, 2 XOR, 3 assign, and 4 read. Mutating operations read the register, reject raw `0xffffffff`, apply the operation, and read back. Crucially, the state helper applies its operator to a local copy: querying state must not write the hardware register. Zero request state means ready; response state must be nonzero and not the removal sentinel.

The TM initializer at `0xb0a6` inherits the SCSI definitions and selects PCI entry 4 for its request (`0xb21e/0xb2c4`) and endpoint entry 1 for its response (`0xb26e/0xb2fe`). `ClearAndEnableInterrupts` at `0x8c22` uses endpoint entry 5 as the interface-version-3-or-later summary interrupt. Definition blocks have a nine-word prefix; the original SCSI initializer copies seven PCI entries and six endpoint entries. The prefix is not interpreted by the new engine.

Additional bounded ARM corroboration: `GetInterruptState` at `0x11928` reads entry `+0x14`, stores the register value locally, and calls the operator with that local address. `ApplyOperator` at `0x11ce8` contains the same five operations. Trigger/clear/enable/disable at `0x11a78`, `0x11b14`, `0x11bb0`, and `0x11c4c` use the same register/operand/operator offsets; their unused size words are not corroborated by these accesses. The ARM TM builder at `0x1abfc` stores fixed size `0x58`, adds `count << 4` at `0x1aff4..0x1affc`, and selects the count-equals-one branch at `0x1b000..0x1b014` with the same pointer copy, length zero, and direct flag 8. The original supports other counts too; OpenDrobo implements only this branch. These excerpts do not establish full ARM semantic equivalence or hardware compatibility.

The original start/stop helpers (`0x29b4`, `0x2afa`) enable/disable delivery and create/destroy target zero. Removal marks channels terminating before failing requests, closes channels, and releases BAR mappings (`0x24b4`, `0x1ebe`, `0x209a`, `0x2bc2`). These are sequencing observations, not a proof that a timeout or disconnect drained outstanding DMA. OpenDrobo deliberately retains uncertain ownership rather than copying the old polling loops or inventing a drain acknowledgment.

`InitializeDMASpecification` at `0x1938` requests 32-bit output addresses, maximum segment `0x80000`, maximum transfer `0x100000`, and alignment 1 with the original mapper. OpenDrobo checks these bounds without treating CPU addresses as bus addresses. The initial controller further restricts request and payload to one segment each.

## DriverKit path and present implementation

Apple documents [IOUserSCSIParallelInterfaceController](https://developer.apple.com/documentation/scsicontrollerdriverkit/iouserscsiparallelinterfacecontroller) as the base for a PCI-backed SCSI controller. Its required personality uses `IOPCIDevice` as provider. The [PCI transport entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.driverkit.transport.pci) scopes supported PCI devices, and the [SCSI controller family entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.driverkit.family.scsicontroller) covers the controller family. Declaring these keys does not grant provisioning or activation approval.

The installed DriverKit 25.2 SDK exposes PCI BAR access, interrupt configuration, I/O buffer descriptors, DMA preparation/completion, and SCSI task/response interfaces for ARM64. The implementation now includes an actual `IOUserSCSIParallelInterfaceController` subclass and a locally linked, hardware-disabled research bundle. The current source covers target/task callbacks, storage framing and inline queries; it does not establish working target publication, DMA, interrupts, or mounts on hardware. Complete SCSI behavior, reset, sleep/wake, a verified bus-master drain mechanism and provisioning remain open.

`platform/macos/driverkit/ReadOnlyTaskAdapter.cpp` projects the actual SDK task type into an independently defined input record. Its pure C policy permits only a bounded initial set of reads and inline read queries. It rejects management writes, firmware/vendor opcodes, power changes, unsupported target/LUN scope, bad directions/counts, and 32-bit DMA-range overflow. READ CAPACITY plans are explicitly marked as virtual geometry. This policy currently supports target 0/LUN 0 and 512-byte block reads only.

The new components under `platform/macos/driverkit/` are:

- `DmaOwnership`: caller-owned mapping leases with 32-bit range, exact-length, segment-count, segment-size and device-permission checks. A known preparation failure with no mapping releases its resources. An uncertain preparation or post-prepare validation failure retains an unpublished mapping for cleanup; failed completion retains ownership for retry. Published timeout/removal quarantines the mapping until independent quiescence is established. Timeout alone cannot clear quarantine.
- `InterruptProgram`: bounded definition parsing and injected MMIO execution. It validates aligned in-range registers and operators before callbacks, computes state locally, stops after backend errors, and treats all-ones status reads as removal.
- `ControllerTransport`: one-shot version-4, target-0/LUN-0 engine with selectable storage or management queues. It checks directory regions, fixed LUN coverage, request windows, selected interrupt definitions, and same-provider request/payload DMA. It encodes the 104-byte direct TM request or experimental 144-byte storage read, publishes descriptors before count/doorbell, and validates the entire completion batch before acknowledgment/reclamation. Storage requires checked 512-byte logical geometry, exact transfer bytes and LBA bounds. External-summary mode lets the service manage one shared cause across both channels. Transaction IDs do not wrap within an instance; bad/stale/duplicate replies, oversized transfers, clock rollback, timeouts and removal cannot silently recycle a live DMA address.
- `DriverKitDma`: actual SDK [PrepareForDMA](https://developer.apple.com/documentation/driverkit/iodmacommand/preparefordma), [CompleteDMA](https://developer.apple.com/documentation/driverkit/iodmacommand/completedma), and `PerformOperation` calls. Commands retain the supplied PCI provider. Permissions come from SDK preparation flags; an unknown preparation result preserves the command and descriptor. Request bytes are copied through the prepared DMA mapping, including any bounce buffer, rather than assuming a CPU mapping names the device-visible bytes.
- `DriverKitSession`: exclusive PCI open, BAR-to-memory-index lookup, bounded SDK accessors, explicit interrupt enable and bus-master gating, and asynchronous disable/cancel completion before resource release. The caller must serialize all calls on the supplied queue; the session does not dispatch or assert that contract. Interrupt delivery uses that queue and a service-owned action. Failed setup/cancellation retains the required objects for close/retry. The owner must keep this session alive until callbacks finish. PCI Close and interrupt cancellation never manufacture a DMA-drain proof.

The SDK [IOInterruptDispatchSource](https://developer.apple.com/documentation/driverkit/iointerruptdispatchsource) supports MSI for PCI providers. The installed `IOInterruptDispatchSource.h` documents the completion after disabled/pending handlers finish and cancellation after callbacks finish. `IOLib.h` exposes `OSSynchronizeIO`; the adapter uses it for ordering. Ordering calls and successful compilation alone do not establish a hardware cache-coherency or PCI drain guarantee.

`scripts/check_driverkit.py` now generates the service interface with IIG, compiles twelve ARM64 objects, links an inactive `.dext`, and runs seven AddressSanitizer/UndefinedBehaviorSanitizer suites: policy, DMA ownership, interrupt program, controller, inline SCSI responses, task ownership, and graceful drain. The controller suite retains independent wire bytes, multiple slots/out-of-order completions, stale slot reuse, permissions, 15 submission failure positions, partial startup, 17 shutdown failure positions with retry, and explicit drain gates. New cases connect the real queue engine, DMA leases, action table and drain policy: empty response batches keep live work pending, matched replies complete leases, retained actions must also finish, and stale replies/timeouts/removal cannot fabricate a drain. Only mocks run; actual SDK methods and generated RPC callbacks compile/link but are not executed.

## Inactive SCSI service and storage reads

`OpenDroboSCSIController.iig` declares the real SDK subclass, lifecycle, target/task, DMA-specification, ordinary asynchronous task, interrupt and timer callbacks. The service declines bundled buffers and uses individually retained completion actions. It requests a fresh descriptor using [UserGetDataBuffer](https://developer.apple.com/documentation/scsicontrollerdriverkit/iouserscsiparallelinterfacecontroller/usergetdatabuffer), then prepares its own DMA mappings; it never reuses `fBufferIOVMAddr` after that call. Completion uses the supplied action and [ParallelTaskCompletion](https://developer.apple.com/documentation/scsicontrollerdriverkit/iouserscsiparallelinterfacecontroller/paralleltaskcompletion). Unsupported writes, resets and task-management operations do not reach the enclosure.

The default DriverKit queue owns mutable service/task state and source callbacks. A separate auxiliary queue performs target creation/destruction so framework initialization can call back on the default queue. Graceful Stop/power-down now blocks admission while timer/interrupt completion polling stays active. Source closure follows zero pending actions and zero live owned leases, or a fault/deadline that preserves unfinished resources. Closing cancels timer/interrupt delivery, waits for callbacks, releases source actions, and drains tracked auxiliary work before final lifecycle acknowledgment; pending actions or leases prevent that acknowledgment. Partial initialization has the same serialized cleanup path. A failed startup releases its extra self retain after cleanup without assuming the framework will call Stop. An uncertain mapping or published timeout retains both descriptors and framework action; the service never claims DMA quiescence after PCI Close. Failed cancellation or an unproven drain leaves resources pinned. This conservative incomplete lifecycle is another reason the artifact remains disabled.

`ScsiTaskTable` is shared by the service and host tests. It owns one retain per accepted action, rejects duplicate pending task IDs, checks transaction association and both DMA leases before framework completion, removes the entry before reentrant callbacks, and snapshots callbacks so completion may destroy the table without a later table access. The caller keeps callback context alive through release. `ScsiResponses` emits bounded TEST UNIT READY, READ CAPACITY(10/16), REPORT LUNS and INQUIRY standard/VPD00/80 replies. Inquiry identifies the project bridge and its registry attachment, not a verified enclosure model/serial. READ CAPACITY preserves validated logical LUN geometry, including its virtual ceiling.

REA queried the original storage builder at `0x6d9a`, with exact pseudocode/assembly receipts under `artifacts/reports/scsi/original`. The fixed storage extension is `0x80`; one 16-byte SGL entry produces a 144-byte request. Recovered fields are flags at `+0x30` (`0x400032` for data-in), byte count `+0x34`, LUN u32 `+0x40`, block count u32 `+0x48`, LBA u64 `+0x50`, request tag u64 `+0x60`, and SGL entries at `+0x80` (address u64, length u32, reserved word). Common framing remains self-DMA address, queue/transaction, opaque cookie, size and channel type 1. The read encoder rejects writes, geometry overflow, a final LBA outside the LUN and mismatched mapping lengths.

Bounded ARM corroboration: storage builder `0x12a2c` stores flags/byte count at `0x12cb8`, request-plus-`0x80` at host field `+0x38` at `0x12cbc..0x12cc0`, LUN at `0x12cc4`, block count at `0x12be8/0x12c54/0x12c70`, LBA at `0x12c90..0x12c94`, generated tag at `0x12cd0..0x12ce0`, and fixed size `0x80` at `0x12d24..0x12d28`. This excerpt does not independently prove final SGL contents/count sizing, all common-prefix fields, direction labels, or firmware use of the host pointer. The byte-vector encoder relies on the separately recovered x86 evidence for those layout facts.

**Recovered storage field, scoped to 5D read paths:** bridge DWARF identifies the request at SRB `+0x30`, its `dataBuffer` union at request `+0x08` (SRB `+0x38`), `sglRegion` at request `+0x28`, and the inline `sglList` at SRB `+0x80`. Request type DIE `0x000a608b` is 56 bytes; the eight-byte address union is DIE `0x000a61e2`; the containing SRB is DIE `0x000a8b2a`. Thus `+0x38` is a direct-buffer field, not an opaque cookie. The original host writes a CPU virtual SGL address there, but the examined SGL read branches do not use that value as their DMA address.

Numeric ARM assembly resolves the mode selection independently of decompiler enum aliases. `processSCSIReadOperationSinglePass` at `0x229a034` tests flags `0x18` at `0x229a5f8`; bit `0x08` selects request `+0x08` at `0x229a618..0x229a628`. Otherwise bit `0x10` selects the saved SRB `+0x80` SGL at `0x229a634..0x229a640`, passed to `pcieDmaTransferWithSGL` at `0x229a660`. `pcieProcessReadResponseMultiIssue` at `0x229ba78` repeats the numeric `0x08`/`0x10` tests at `0x229beec`/`0x229bf04`, selecting SRB `+0x80` at `0x229bf0c`. OpenDrobo's flags `0x400032` set `0x10` and clear `0x08`, so the encoder keeps the inactive `+0x38` field zero and supplies only mapped bus addresses in the inline SGL. No request bytes change in this slice. This resolves the selected mode's field choice; other firmware/model paths and hardware compatibility remain unverified.

`scripts/build_driverkit.py` creates `artifacts/driverkit/OpenDroboStorage.dext` from project source plus generated IIG code, using only Apple DriverKit/PCI/SCSI frameworks and the SDK C++ runtime. Xcode's `Iig.xcspec` specifies architecture-neutral interface generation; ARM64 selection belongs to compilation. Inherited completion TYPE annotations use the qualified base-method name to avoid the installed IIG assertion. The build is local, unprovisioned and not embedded or installed. `od_scsi_service_hardware_enabled()` returns zero before PCI open or framework Start; plist/preferences cannot turn it on. This checkpoint does not provide complete SCSI sense/mode-page behavior, reset/sleep/wake, a verified global hardware-quiescence mechanism, or a supported loadable replacement driver.

## Completion-based drain and remaining hardware boundary

Original host `HostSleepEvent` at x86 `0x67f6` closes admission and polls an outstanding count in one-second steps, with a 30-second timeout. Its timeout return is not a DMA-drain guarantee. Bridge `mvDmaTransferWithSGLEx` at `0x22a2da4` distinguishes blocking and asynchronous submissions; asynchronous submission retains its descriptor chain. The multi-issue read response path calls `mvDMAWaitForTransferCompletion` at `0x229c10c` and `0x229c154` before posting its request completion at `0x229c31c`. The wait helper at `0x22a32e4` calls `esaXORWaitForCompletion` (`0x207050c`), checks status, calculates realized bytes on success, then frees the descriptor chain. The underlying helper waits on the channel semaphore and returns its error status. This supports per-request completion ordering in the examined path; it does not prove a global posted-write fence or removal-time drain.

`ScsiDrain.h/.c` supplies the shared caller-owned policy. It closes admission, permits completion polling, enforces a fixed absolute monotonic deadline and bounded counts, and authorizes source closure only after both action and lease counts reach zero. Zero response count alone is insufficient. Repeated begin cannot extend the deadline; clock rollback, inconsistent counts, timeout with live resources and explicit failure quarantine permanently. Neither observed zero counts nor the policy itself asserts hardware quiescence.

The SDK service uses this policy for normal Stop and power-down with a 30-second bound. It retains itself while completion work continues. The queue engine validates transaction identity and the complete response batch before completing mappings; the action table separately checks both leases before notifying the framework. Source-close cleanup always passes **false** for bus-master-quiescent to the core; faulted published leases stay quarantined. This design can finish a normal owned-request drain without inventing a hardware-wide attestation. Stronger runtime service mocks, removal/recovery, reset and restart still need work.

The installed SDK's `IOPCIDevice::Close` comment describes disabling bus mastering and memory-space enable; `IODMACommand::CompleteDMA` ends mapping ownership. Neither documents a global hardware-drain guarantee. PCI config reads, link/device reset completion and `OSSynchronizeIO` ordering are likewise not used as that proof. Apple's [Stop contract](https://developer.apple.com/documentation/driverkit/ioservice/stop) requires stopping I/O and quiescing hardware before calling superclass Stop. Successful compilation and host mocks cannot establish that hardware contract; provisioning/activation remain closed.

## Relation to BeyondRAID and Finder

The enclosure firmware already converts its protected array into logical LUN data. A replacement host transport can use that interface without first reimplementing on-device BeyondRAID. Independent member-image recovery is a separate path; [the RMR recovery note](BEYONDRAID_LAYOUT.md) records its newly resolved checksum boundary.

Finder reporting still needs a verified capacity record, device/LUN binding, and a working mounted filesystem view. The current application and FSKit module retain their unconfirmed-unit gate. No hardware, original-driver-free connection, mount, or Finder capacity change has been demonstrated by this offline slice.
